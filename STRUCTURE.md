# Project layout

Directory map: where each file lives, one line each. `PLAN.md` says what a pass does and why;
`OPEN_QUESTIONS.md` holds what is unresolved. Neither is repeated here. Keep in sync when files
move.

## Root modules
- `Fugue.lean` — CLI entry point, the `lean_exe` root.
- `Common.lean`, `Core.lean`, `Desugarer.lean`, `Driver.lean`, `Elaborator.lean`, `Parser_.lean`,
  `ProgressBar.lean`, `Tests.lean`, `WellFormedness.lean` — per-library re-export roots.
- `Computable2Guarded.lean`, `Guarded2Network.lean`, `Network2Go.lean`, `Typed2Computable.lean` —
  pass entry points, each re-exporting its directory.
- `VerifiedCompiler.lean` — proof-infrastructure library root.
- `CustomPrelude.lean` — project-wide prelude imports, notations and tactics.
- `lakefile.lean` — build configuration, one `lean_lib` per pass, and the compiler's version.
- `lean-toolchain`, `lake-manifest.json` — toolchain pin and dependency lockfile.
- `fugue.sh` — dev-mode CLI wrapper.
- `.actrc` — local `act` runner-image map for testing the CI workflow.
- `.lake/version/Version.lean` — generated by `lakefile.lean`, not in the repo; carries the version
  string into compiled code.
- `LEAN_STYLE.md` — canonical Lean rules: proof style, conventions, tactic playbook.
- `AGENTS.md` — agent-mode configuration for non-Claude-Code agents.

## `Common/`
- `Errors.lean` — diagnostic typeclasses and rendering.
- `Position.lean` — `SourceSpan` and the out-of-band source-position map.
- `Flags.lean` — CLI flag definitions and dump-artifact handling.
- `Fresh.lean` — hygienic fresh-name effect class and its lifts.
- `Pretty.lean` — precedence-aware `Std.Format` combinators.
- `Diagnostics/Code.lean` — `Severity` and `DiagnosticCode`.
- `Diagnostics/Stage.lean` — the pipeline's stages as data.
- `Diagnostics/Registry.lean` — every diagnostic code with its stage, `-W` name and summary.

## `Extra/`
Generic data-structure lemmas and instances.
- `AList.lean`, `Array.lean`, `AssocList.lean`, `Fin.lean`, `Finmap.lean`, `Finset.lean`,
  `HashMap.lean`, `List.lean`, `Monad.lean`, `Nat.lean`, `Option.lean`, `Prod.lean`, `Prop.lean`,
  `Set.lean`, `String.lean`, `Substring.lean`, `Sum.lean` — per-type lemmas.
- `Rel.lean` — relation composition, iteration and the `OmegaProd` class.
- `Seq.lean` — `Stream'.Seq` as the trace monoid, plus infinite products.
- `Do.lean` — `Std.Do` spec lemmas the toolchain does not ship.
- `Mathlib/Tactic/DeriveTraversable.lean` — vendored `Traversable` derivation.

## `ProgressBar/`
- `Spinner.lean`, `SpinnerData.lean`, `Spinners.lean` — CLI spinner rendering and frame data.

## `Parser_/`
- `PlusCal.lean`, `TLAPlus.lean` — the two parsers.
- `Common.lean` — shared combinators.
- `Monad.lean` — the parser monad stack.
- `Annotations.lean` — `@type`/`@parameter` annotation parsing.
- `Tokens/PlusCal.lean`, `Tokens/TLAPlus.lean` — token definitions.

## `Desugarer/`
- `PlusCal.lean` — statement and process desugaring, well-labelledness checks.
- `TLAPlus.lean` — expression desugaring.
- `Errors.lean`, `Monad.lean` — diagnostics and monad stack.

## `WellFormedness/`
- `WellFormedness.lean` — ties the checks together; the driver's entry point.
- `Errors.lean` — errors and the `unusedMailbox` warning.
- `Monad.lean` — `MonadForeignLookup` and its lifts.
- `Reachability.lean` — the shared reachability walk.
- `Labelling.lean` — `goto` targets and `"Done"`.
- `Declarations.lean` — declaration-shape restrictions.
- `Restrictions.lean` — the walk's checks, plus receive-channel checking and mailbox rewriting.
- `WellScoped.lean` — re-export of the scoping checks.
- `WellScoped/TypedPlusCal.lean` — the executable scoping check.
- `WellScoped/CorePlusCal.lean`, `WellScoped/GuardedPlusCal.lean` — `Prop`-side counterparts.

## `Elaborator/`
- `Elaborator.lean` — module checking entry point.
- `Monad.lean` — context, metavariables, errors, fresh names.
- `Context.lean` — `Γ`-extension helpers.
- `Subtyping.lean` — `<:`, `lub`, `glb`, coercions, metavariable solving.
- `Resolution.lean` — metavariable resolution.
- `TypeUtils.lean` — type-level helpers.
- `Expressions.lean` — `checkExpr`/`inferExpr`.
- `Declarations.lean` — declaration and module checking.
- `PlusCal.lean` — statement, process and algorithm checking.
- `Errors.lean` — `TCError` variants.

## `Core/`
- `Declaration.lean` — `Declaration`/`Module`, generic over the expression former.

## `Core/SurfacePlusCal/`, `Core/SurfaceTLAPlus/`
- `Syntax.lean` (each) — parser-output ASTs, annotations attached.
- `Pretty.lean` (each) — pretty-printers for parse dumps.

## `Core/CorePlusCal/`, `Core/CoreTLAPlus/`
- `Syntax.lean` (each) — desugared ASTs, annotations resolved into fields.

## `Core/TypedPlusCal/`, `Core/TypedTLAPlus/`
- `Syntax.lean` (each) — elaborator-output ASTs, every annotation a concrete `Typ`.
- `Coercion.lean` — term-level coercions.
- `Subst.lean` (`TypedTLAPlus` only) — de Bruijn index manipulation (`liftBound`/`openVar`/`close`).
- `Builtins.lean` — the builtin-operator table.

## `Core/ComputablePlusCal/`, `Core/ComputableTLAPlus/`
- `Syntax.lean` (each) — the computable fragment's ASTs.
- `Coercion.lean` — coercions over that fragment.
- `FreeVars.lean` — free-variable and freshness predicates.
- `Subst.lean` — substitution.
- `Semantics/Interface.lean` — `ExprSemantics`, the abstract expression layer.
- `Semantics/Value.lean` — the concrete value domain `Value := ZFSet` and its literal encodings.
- `Semantics/Operational.lean` — the concrete `ExprSemantics Value` instance: `Eval` as an inductive relation.

## `Core/GuardedPlusCal/`
- `Syntax.lean` — the flat statement AST and `Block`'s list-like interface.
- `Syntax/Lemmas.lean` — structural facts and induction principles for `Block`.
- `Semantics/Denotational.lean` — behaviors, traces, states, statement and block semantics.
- `Semantics/Lemmas.lean` — block equations and relabelling lemmas.
- `Semantics/Process.lean` — the process and algorithm layers.

## `Core/NetworkPlusCal/`
- `Syntax.lean` — the statement AST without `receive`, plus `Thread.rx`.
- `Semantics/Denotational.lean` — this language's statement semantics and thread labels.
- `Semantics/Lemmas.lean` — block equations and relabelling lemmas.
- `Semantics/Process.lean` — its process and algorithm layers.

## `Core/Go/`
- `Syntax.lean` — the Go AST this compiler targets.
- `Pretty.lean` — the code generator: what the shipped `.go` file is printed by.

## `Typed2Computable/`
- `Typed2Computable.lean` — entry point.
- `TLAPlus.lean` — expression translation.
- `PlusCal.lean` — statement and algorithm translation.
- `Errors.lean` — `ComputableError`.

## `Computable2Guarded/`
- `Computable2Guarded.lean` — entry point.
- `CFlow.lean` — rewrites `if`/`while` into `either`/`await`.
- `Par.lean` — sequentializes parallel assignments.
- `FlatReord.lean` — flattening and guard reordering, in one walk.
- `Errors.lean` — `GuardedError`.

## `Guarded2Network/`
- `Guarded2Network.lean` — entry point, importing the proofs so the build checks them.
- `CorrectInstance.lean` — the pass's correctness at the concrete `Value` semantics, with `ExprSemantics`/`SeqBuiltins` discharged and the sorry-free check.
- `PlusCal.lean` — the pass.
- `Errors.lean` — `G2NError`.
- `Lemmas.lean` — proof support and the aggregator for the files below.
- `Lemmas/Monad.lean` — the monad the pass is pinned to for proofs.
- `Lemmas/Trace.lean` — this pass's trace relation.
- `Lemmas/Seq.lean` — the sequence-builtin laws the pass's generated expressions obey.
- `Lemmas/Relation.lean` — the refinement invariant and its algorithm-level lift.
- `Lemmas/Statement.lean` — evaluation transfer and the action-statement equations.
- `Lemmas/Reorder.lean` — commuting an assignment past a guard.
- `Lemmas/Rx.lean` — facts about receiving threads.
- `Lemmas/Locality.lean` — what a step leaves alone.
- `Lemmas/Precondition.lean` — the precondition walk and `receive` elimination.
- `Lemmas/AtomicBranch.lean` — one branch.
- `Lemmas/AtomicBlock.lean` — one block.
- `Lemmas/Thread.lean` — one thread.
- `Lemmas/Process.lean` — one process, and label disjointness.
- `Lemmas/Algorithm.lean` — the algorithm level and the pass's correctness theorem.
- `Lemmas/Blocking.lean` — the blocking half of the algorithm-level refinement.
- `Lemmas/Correctness.lean` — the packaging as a `Compiler.Correctness`.

## `Network2Go/`
- `Network2Go.lean` — entry point.
- `Naming.lean` — identifier escaping and the renaming schemes.
- `Typ.lean` — TLA⁺ types into Go types.
- `Ord.lean` — ordering dictionaries.
- `Expression.lean` — TLA⁺ expressions into Go expressions.
- `Definition.lean` — operator and function definitions into top-level declarations.
- `PlusCal.lean` — processes, threads, blocks and branches into Go functions.
- `Locks.lean` — lock inference.
- `Emit.lean` — a declaration list as a `.go` file.
- `Errors.lean` — `N2GError`.

## `Network2JoinCalculus/`
Network PlusCal to Join Calculus. No files yet.

## `Driver/`
- `Modules.lean` — `EXTENDS` resolution, the module cache, and the driver monad.
- `Pipeline.lean` — a whole compile as one function, plus diagnostic rendering.
- `Errors.lean` — the driver's wrapper error type.
- `Builtins.lean` — the standard-library operator table.

## `VerifiedCompiler/`
Generic proof infrastructure.
- `Trace.lean` — the trace class and its relation algebra.
- `Relation.lean` — relation definitions the framework builds on.
- `ClosedForm.lean` — productivity, the fixed-point identities, and their closed forms.
- `Denotational/StrongRefinement.lean` — the refinement relation and its preservation lemmas.
- `Denotational/Notations.lean` — notation for the above.
- `Denotational/Tactics.lean` — tactics for discharging refinement obligations.
- `Denotational/Correctness.lean` — what a pass being correct means, and how two compose.

## `Tests/`
- `Main.lean` — fixture discovery, the CLI, and the run loop.
- `Expectation.lean` — what a fixture claims, from its filename and sidecar.
- `Check.lean` — one function per assertion.
- `GoBuild.lean` — writes emitted Go to a temp module and runs `go build`.
- `Report.lean` — verdicts and how they print.
- `regression/` — `Accept*.tla`/`Reject*.tla` fixtures with optional `.expect.json` sidecars.
- `regression/_stubs/AcceptInVariableWithoutParameter.go` — Go definitions a `goBuild` fixture needs.
- `examples/` — larger worked examples, not run by `lake test`.

## `runtime/`
Go, not Lean — the library generated code links against. Every package is a subdirectory.

### `runtime/comm/`
- `comm.go` — `Sender[T]`/`Receiver[T]` interfaces.
- `multicast.go` — the compiled form of a `multicast` statement.
- `address.go` — `Address` and its ordering dictionary.
- `comm_test.go`, `multicast_test.go`, `address_test.go` — their tests.

### `runtime/locks/`
- `locks.go` — `Lock[T]`, `MkLock`, `Acquire`, `Release`.
- `locks_test.go` — its tests.

### `runtime/tlaplus/`
- `ord.go` — the equality-and-ordering dictionary struct.
- `bool.go`, `str.go` — `Bool`/`Str` newtypes and their dictionaries.
- `int_big.go`, `int_machine.go` — the two `Int` representations, by build tag.
- `sequences.go` — `Seq[T]` and the `Sequences` module's operations.
- `sets.go` — `Set[T]` and the set operations.
- `functions.go` — `LazyFunction[T, U]` and function construction.
- `naturals.go` — `IntRange`.
- `print.go` — what PlusCal's `print` compiles to.
- `helpers_test.go`, `int_test.go`, `int_big_test.go`, `functions_test.go`, `naturals_test.go`,
  `records_test.go`, `sequences_test.go`, `sets_test.go`, `str_test.go`, `downcasts_test.go` — their tests.

## `persistent/`
Go, not Lean — data structures the runtime needs. Root `go.mod` covers this directory and
`runtime/`.
- `treemap/node.go`, `treemap/balance.go`, `treemap/treemap.go`, `treemap/iter.go` — a persistent
  ordered map with a caller-supplied comparison.
- `treemap/treemap_test.go` — its tests.

## `reference/`

Reference material (spec sources, generated API references, mapping docs). File names withheld
here on purpose — see this directory directly for contents.

## `docs/`
- `diagnostics/<code>.md` — one page per diagnostic code, printed by `fugue explain`.

## `scripts/`
- `DumpFacts.lean` — extracts local theorems, class fields and tactics into the fact database.
- `facts` — queries and curates that database.
- `lean-style` — checks `.lean` sources against the mechanically-checkable style rules.
- `structure-check` — checks this file against the tree.

## `.github/`
- `workflows/ci.yml` — build+test matrix, release publish, documentation deploy.
- `act-events/push-master.json` — event payload for local `act` runs of the master-only jobs.

## `.claude/`
- `plans/` — in-flight plan documents.
- `skills/` — agent skills available in this checkout.
- `FINDINGS.md` — implementation findings log.
- `facts/` — the local fact database, queried through `scripts/facts`.
- `settings.json`, `settings.local.json` — Claude Code settings, untracked.
- `hooks/git-guardrails.sh` — blocks mutating git commands.
- `hooks/facts-steer.sh` — steers declaration greps to `scripts/facts`.
- `hooks/lean-reminder.sh` — bounds unbounded `.lean` reads.
- `hooks/lean-style-check.sh` — runs `scripts/lean-style` on `Stop`.
- `hooks/structure-check.sh` — runs `scripts/structure-check` on `Stop`.
