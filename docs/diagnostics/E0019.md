# E0019: invalid record field access

The right-hand side of a record-access `.` is not a bare field-name identifier.

`.` parses as an ordinary infix operator, so `r.(1)` or `r.f()` is syntactically fine. But a
record field is named by an identifier and nothing else, so the desugarer rejects anything on the
right of `.` that is not one. This is purely syntactic — it fires regardless of `r`'s type.

## Why it fires

```tla
---- MODULE Example ----
CONSTANTS
    \* @type: Address;
    PID

(*--algorithm Example {
    variable r = [a |-> 1];
    process (P = PID) {
    p1: print r.(1);
        goto Done;
    }
}*)
====
```

`r.(1)` — the right side of `.` is `(1)`, not a field name.

## How to fix it

- Use a plain field name: `r.a`.
- To index by a computed key, use a function, not a record: `f[k]`.
