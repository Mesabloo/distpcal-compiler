# E0060: internal invariant violated in Network2Go

A compiler bug, not a problem with your specification.

The Go backend relies on guarantees the earlier passes establish — every channel reference
resolved, every process's threads well-formed, every TLA⁺ expression well-typed. This diagnostic
fires when one of those did not hold. A well-formed program that gets this far through the
pipeline should never reach it. It is distinct from `E0061`, which is a real limitation on
well-formed input.

## Why it fires

A guarantee an earlier pass was supposed to have established did not hold. The message names it.

## How to fix it

- Report it, with the specification and the message text.

## See also

- `E0061` — a well-typed construct the Go backend genuinely cannot compile (a real error, not a
  bug).
- `E0056`, `E0057`, `E0058` — the same kind of internal-invariant check in the earlier passes.
