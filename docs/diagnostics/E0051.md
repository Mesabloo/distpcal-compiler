# E0051: algorithm-level 'variables' block

The PlusCal algorithm declares `variables` at its own level, outside any process.

Algorithm-level `variables` are state shared across every process. A distributed algorithm has no
shared memory — each process compiles to a separate unit — so this is disallowed. Only `fifos`
(shared *channels*) may appear at algorithm level. Per-process `variables` are fine.

## Why it fires

```tla
---- MODULE Example ----
CONSTANTS
    \* @type: Address;
    PID

(*--algorithm Example {
    variables x = 0;
    process (P = PID) {
    p1: skip;
    }
}*)
====
```

`variables x = 0` sits at algorithm level.

## How to fix it

- Move the declaration inside the process that uses it (per-process local state).
- If several processes need to agree on a value, pass it as a `CONSTANTS` input, or communicate it
  over a `fifos` channel.
