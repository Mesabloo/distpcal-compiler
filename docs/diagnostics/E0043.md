# E0043: type left undetermined

A declaration's type still has an open type variable in it once checking it is done, and nothing
in the declaration ever fixed what that variable stands for.

A polymorphic operator has a type variable in its signature — `(a) => a`. Each place it is used
gets its own copy of that variable, filled in by how it is used there. A use that fills in
nothing — the operator is named as a value but never called — leaves the variable open.

## Why it fires

```tla
---- MODULE Example ----
CONSTANTS
    \* @type: Address;
    PID

\* @type: (a) => a;
Id(x) == x

(*--algorithm Example {
    process (P = PID) {
    p1: with (y = Id) {
            skip;
        };
        goto Done;
    }
}*)
====
```

`Id` is bound to `y` as a bare value and never called, so its `a` is never instantiated.

## How to fix it

- Use the value at a concrete type — call the operator, or annotate the binding.
- If it is genuinely unused, remove it.

## See also

- `E0028` — a type that cannot be inferred at a position.
- `E0036` — several parts with no common type.
