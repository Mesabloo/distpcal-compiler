# E0021: module not found

An `EXTENDS` clause names a module that no search path provides.

`EXTENDS Foo` looks for `Foo.tla` in the extending module's own directory, then in each `-I`
search path, then in the compiler's builtin standard-library table. If none has it, resolution
stops here.

## Why it fires

```tla
---- MODULE Example ----
EXTENDS Nonexistent
====
```

No `Nonexistent.tla` on any search path, and no builtin module by that name.

## How to fix it

- Check the spelling and case — `EXTENDS Foo` resolves to `Foo.tla` exactly, nothing else.
- If the module is in another directory, add it with `-I <dir>` (comma-separate several:
  `-I dir1,dir2`).
- Standard modules — `Naturals`, `Integers`, `Sequences`, `FiniteSets`, `Bags`, `TLC`, `Fugue` —
  are builtin and need no file.

## See also

- `E0022` — the module name resolves to more than one file.
- `E0023` — `EXTENDS` forms a cycle.
