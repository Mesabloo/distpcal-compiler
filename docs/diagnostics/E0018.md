# E0018: conflicting assignment

The same variable is written more than once within one atomic block, on the same control path.

A labelled block is one atomic step. Writing a variable twice in it — through `x := e`, a `||`
parallel assignment, or a `receive` target, in any combination — has no well-defined meaning:
there is no ordering between writes in a single step. The check is by *base* variable, so
`x[0] := 1; x[1] := 2` conflicts too; deciding whether two indexed writes actually alias is out
of scope.

## Why it fires

```tla
---- MODULE Example ----
(*--algorithm Example {
    variables x = 0;
    process (P = 0) {
    p1: x := 4;
        x := 0;
        goto Done;
    }
}*)
====
```

`x` is written twice in block `p1`.

## How to fix it

- Split the writes across two labelled blocks — the second write then happens in the next atomic
  step.
- If you meant one combined update, write it as a single expression: `x := f(x)`.
- Two `if` branches writing the same variable is fine; a branch write followed by a write after
  the `if` is a conflict on the path that took the branch.
