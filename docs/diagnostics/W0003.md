# W0003: repeated @parameter annotation

A `@parameter` annotation appears more than once on the same declaration.

`@parameter` is a content-free marker: it says a process-local variable initialized with `\in` is
an input the caller supplies, not a nondeterministic choice. It carries nothing that a second
copy could contradict, so a repeat is merely redundant — the compiler keeps one and drops the
rest. A repeated `@type` or `@mailbox`, which do carry content, is a hard error instead (`E0017`).

## Why it fires

```tla
process (P = PID)
    variable
        \* @parameter
        \* @parameter
        x \in {"a", "b"};
```

Two `@parameter` markers on `x`. One is enough.

## How to fix it

- Delete the extra annotations, leaving one.
- If the repetition is deliberate — generated code, a template — the warning is harmless: silence
  it with `-Wno-duplicate-parameter`.

## See also

- `E0017` — the same annotation kind twice where the copies could disagree (`@type`, `@mailbox`).
- `E0016` — `@parameter` on a site that does not take it, such as a `=`-initialized variable.
