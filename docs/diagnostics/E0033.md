# E0033: invalid tuple index

A tuple was indexed with something that is not a literal number, or with a literal outside the
tuple's range.

Each component of a tuple can have its own type, so the checker has to know *which* component at
check time to give the access a type. That rules out a variable index, and requires a literal
between 1 and the tuple's length.

## Why it fires

```tla
---- MODULE Example ----
CONSTANTS
    \* @type: Address;
    PID

(*--algorithm Example {
    process (P = PID) {
    p1: print <<1, 2>>[3];
        goto Done;
    }
}*)
====
```

`<<1, 2>>` has two components; index `3` is out of range. A non-literal index like `<<1, 2>>[i]`
fails the same check.

## How to fix it

- Use a literal index within range: `<<1, 2>>[1]` or `[2]`.
- If you need a computed index, use a sequence or a function instead of a tuple — those allow it,
  at the cost of one element type for all positions.

## See also

- `E0031` — indexing into a type that is not indexable at all.
- `E0038` — a tuple was expected somewhere else.
