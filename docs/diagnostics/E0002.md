# E0002: unexpected token

The parser reached a token that cannot continue the construct it was building.

Every grammar rule has a set of tokens that may come next. When the next token is not one of
them, the parser stops and reports it here, along with what it was expecting. The position is the
offending token itself — or, when something is missing rather than wrong, the token sitting where
the missing piece should be.

## Why it fires

```tla
---- MODULE Example ----
EXTENDS Naturals

\* @type: Int;
Total == 1 +
====
```

`+` needs a right operand. The parser reaches `====` — the end of the module — where that operand
should be, and reports the mismatch there rather than back at the `+`.

## How to fix it

- Supply the missing piece, or remove the token that does not belong. The "expected" list in the
  message says what the parser would have accepted at that point.
- If the error points at a keyword you did not mean as a keyword (`WF_`, `OTHER`, `fair`), you
  have used a reserved word as a name, or in a position the grammar does not allow it.
- If the position looks too late — at a closing bracket or `====` rather than at the real
  mistake — the construct in between parses cleanly on its own; the earlier text is where to
  look.
