# E0062: process receives from more than one channel

A process has `receive` statements naming two different channels.

A process's incoming messages arrive on one channel. Messages from two channels would arrive
interleaved with no way to tell which `receive` each belongs to, so a process may listen on
exactly one.

Two `receive`s naming the *same* channel at different indices (`ch[self]` vs `ch[other]`) count as
two channels — those are distinct FIFOs.

## Why it fires

```tla
---- MODULE Example ----
CONSTANTS
    \* @type: Address;
    PID

(*--algorithm Example {
    fifos
        \* @type: Channel(Int);
        chA,
        \* @type: Channel(Int);
        chB;
    (* @mailbox: chA; *) process (P = PID)
        variables
        \* @type: Int;
        x = 0,
        \* @type: Int;
        y = 0;
    {
    p1: receive(chA, x);
        goto p2;
    p2: receive(chB, y);
        goto Done;
    }
}*)
====
```

`p1` receives on `chA`, `p2` on `chB`.

## How to fix it

- Have the process listen on one channel. If it needs messages of two kinds, send them over one
  channel with a tag (a record field, a variant) and branch on it after receiving.
- Split the work across two processes, one per channel.
