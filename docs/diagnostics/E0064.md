# E0064: receive without a @mailbox

A process contains a `receive` but declares no `@mailbox`.

A receiving process listens on exactly one channel (`E0062`), and it must name that channel
explicitly, in a `@mailbox` annotation on the process. The channel is not inferred from the
`receive` statements.

## Why it fires

```tla
---- MODULE Example ----
CONSTANTS
    \* @type: Address;
    PID

(*--algorithm Example {
    fifos
        \* @type: Channel(Int);
        ch;
    process (P = PID)
        variables
        \* @type: Int;
        x = 0;
    {
    p1: receive(ch, x);
        goto Done;
    }
}*)
====
```

The process receives on `ch` but has no `@mailbox`.

## How to fix it

- Add `@mailbox` immediately before `process`, naming the channel: `(* @mailbox: ch; *) process
  (P = PID)`.
- For a process set, index by `self`: `@mailbox: ch[self]`.

## See also

- `W0007` — the mirror case: a `@mailbox` on a process that never receives (a warning, not an
  error).
- `E0062`, `E0063` — the other constraints on a receiving process.
