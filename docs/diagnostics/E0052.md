# E0052: reference to a module-level VARIABLE

The algorithm references a name that resolves to a TLA⁺ `VARIABLE` declared at module level —
its own, or one reached through `EXTENDS`.

A module-level `VARIABLE` is exactly the kind of implicit shared state a distributed algorithm
cannot have. The message names the module the `VARIABLE` was declared in.

## Why it fires

```tla
---- MODULE Example ----
VARIABLE
    \* @type: Int;
    V

CONSTANTS
    \* @type: Address;
    PID

(*--algorithm Example {
    process (P = PID) {
    p1: assert V = V;
        goto Done;
    }
}*)
====
```

`V` is a module-level `VARIABLE`, referenced from inside the algorithm.

## How to fix it

- Use process-local `variables` for mutable state, `CONSTANTS` for fixed inputs.
- A `VARIABLE` in an `EXTENDS`-ed module is just as disallowed — that module is providing shared
  state through the back door.

- `E0051` — an algorithm-level PlusCal `variables` block, the same restriction from the PlusCal

- `E0053` — a temporal or action operator reachable from a statement.
