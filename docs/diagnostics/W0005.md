# W0005: partial multicast annotation

A `multicast` filter with more than one component carries a `@type` annotation on some components
but not all.

The desugarer collapses a multi-component filter into a single binder over the components'
Cartesian product, whose declared type is the tuple of the components' types. It can only build
that tuple when *every* component supplies a type. Given some and not others, it drops the
annotations entirely and takes the recipient's type from the channel's own declared domain
instead.

Nothing is lost by the drop — the channel's domain fixes the type regardless — so this warns
rather than errors.

## Why it fires

```tla
---- MODULE Example ----
CONSTANTS
    \* @type: Address;
    PID

(*--algorithm Example {
    fifos
        \* @type: <<Address, Address>> -> Channel(Int);
        ch[{PID}];
    process (P = PID) {
    p1: multicast(ch, [(* @type: Address; *) m = PID, y \in {PID} |-> 1]);
        goto Done;
    }
}*)
====
```

`m` is annotated, `y` is not.

## How to fix it

- Annotate every component, or none.
- Silence with `-Wno-partial-multicast-annotation` — the compile is unaffected either way.
- Note: a multi-component `multicast` filter is outside what the Go backend compiles (`E0061`);
  single-component filters need no product and this warning cannot arise for them.
