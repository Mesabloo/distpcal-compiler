# E0036: ambiguous type

Several expressions that must share one type — the branches of an `IF`/`CASE`, the elements of a
set or sequence literal — have types with no common supertype.

For the whole to have a type, one type has to fit all the parts. When none does — no type that
every part converts to — there is nothing to give the `IF`/`CASE`/literal.

## Why it fires

```tla
---- MODULE Example ----
CONSTANTS
    \* @type: Address;
    PID

(*--algorithm Example {
    process (P = PID) {
    p1: print IF TRUE THEN 1 ELSE TRUE;
        goto Done;
    }
}*)
====
```

The `THEN` branch is `Int`, the `ELSE` branch is `Bool`; neither is a subtype of the other.

## How to fix it

- Make the parts agree: convert one so both branches, or all elements, have the same type.
- If they genuinely hold different kinds of value, the construct is wrong — use a record or a
  separate variable per kind.
