# E0034: operator type expected

Something used as an operator does not have an operator type.

An operator type is written with `=>` — `(Int, Int) => Int`. A higher-order parameter `F(_)` in an
operator definition needs its corresponding position in the definition's `@type` to be an operator
type, so its declared arity can be checked against it.

## Why it fires

```tla
---- MODULE Example ----
\* @type: (Int, Int) => Int;
Op(F(_), x) == x
====
```

`F(_)` is a one-argument higher-order parameter, but `Op`'s type gives `F`'s position a plain
`Int` — not an operator type.

## How to fix it

- Give the higher-order parameter an operator type in the annotation: `((Int) => Int, Int) => Int`.
- If `F` is not meant to be higher-order, drop the `(_)`: write `F`, not `F(_)`.

- `E0037` — a function type (`->`) was expected, which is a different thing from an operator type.
