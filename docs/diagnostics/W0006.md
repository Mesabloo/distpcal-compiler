# W0006: algorithm in an EXTENDS-ed module

A module named in an `EXTENDS` clause carries a PlusCal algorithm of its own, which `EXTENDS` does
not import.

`EXTENDS` brings a module's *declarations* into scope — its `CONSTANTS`, `VARIABLES`, operator and
function definitions. An embedded PlusCal algorithm is not a declaration: it is what the compiler
translates when that module is the one being compiled, and it is dropped entirely when the module
is reached through `EXTENDS`. Nothing downstream of resolution mentions it again.

The warning is reported at the identifier in *your* `EXTENDS` clause, not in the file the algorithm
is in: that file is well-formed on its own, and the clause is what would have to change.

## Why it fires

```tla
---- MODULE Worker ----
EXTENDS Naturals

CONSTANTS
    \* @type: Set(Address);
    Workers

\* @type: Int;
Limit == 2

(*--algorithm Worker {
    process (w \in Workers)
        variables
            \* @type: Int;
            done = 0;
    {
    w1: done := done + 1;
        goto Done;
    }
}*)
====
```

```tla
---- MODULE Main ----
EXTENDS Worker

(*--algorithm Main {
    process (m \in Workers) {
    m1: assert Limit = 2;
        goto Done;
    }
}*)
====
```

`Workers` and `Limit` come across. `Worker`'s algorithm does not.

## How to fix it

- If you wanted the declarations only, nothing is wrong — silence it with `-Wno-extends-algorithm`.
- If you wanted the algorithm's behavior, `EXTENDS` is the wrong tool: compile that module
  directly, or move the shared declarations into a third module both extend, leaving each algorithm
  in the module that is compiled for it.
- A module intended purely as a library is clearest with no algorithm in it at all.
