# E0009: goto not in tail position

A `goto` is followed by more statements in the same list, and none of them is a label.

`goto` transfers control away and never returns. Any unlabelled statement after it in the same
block can never run — it is dead code, and rejected rather than silently dropped. A `goto`
followed immediately by a *label* is fine: the label starts a new, reachable block.

## Why it fires

```tla
---- MODULE Example ----
(*--algorithm Example {
    variable x = 0;
    process (P = 0) {
    p1: goto p1;
        print x;
    }
}*)
====
```

`print x` sits after `goto p1` with no label between them, so it is unreachable.

## How to fix it

- Delete the unreachable statements, or move them before the `goto`.
- If they *should* be reachable, they belong under their own label: put a `label:` before them.

## See also

- `E0010` — a statement with no label reachable above it.
- `E0014` — an `if`/`either` that ends a block is not followed by a label.
