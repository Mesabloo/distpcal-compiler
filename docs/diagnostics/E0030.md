# E0030: record type expected

A record access or update (`r.f`, `[r EXCEPT !.f = e]`) was used on something whose type is not a
record.

`.` is an ordinary infix operator syntactically, so `n.f` parses fine; the type checker is what
requires `n` to be a record.

## Why it fires

```tla
---- MODULE Example ----
CONSTANTS
    \* @type: Address;
    PID

(*--algorithm Example {
    variable n = 3;
    process (P = PID) {
    p1: print n.f;
        goto Done;
    }
}*)
====
```

`n` is an `Int` (from `n = 3`), so `n.f` has no field to access.

## How to fix it

- Access `.f` only on a record — `[a |-> 1, b |-> 2]` or a value declared with a record `@type`.
- If `n` should be a record, fix its initialiser or its annotation.

## See also

- `E0019` — the right-hand side of `.` is not a field name.
- `E0032` — a field the record type does not have.
