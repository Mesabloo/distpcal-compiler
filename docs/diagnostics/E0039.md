# E0039: higher-order parameter arity mismatch

A higher-order parameter's declared arity — the number of `_` placeholders in `F(_, _)` — does not
match the arity of its type in the definition's `@type` annotation.

## Why it fires

```tla
---- MODULE Example ----
\* @type: ((Int) => Int, Int) => Int;
Op(F(_, _), x) == x
====
```

`F(_, _)` declares a two-argument operator parameter, but its annotated type `(Int) => Int` takes
one.

## How to fix it

- Match the `_` count to the annotated operator type's parameter count.
- `F(_)` with `(Int) => Int`, `F(_, _)` with `(Int, Int) => Int`.

## See also

- `E0034` — the parameter's annotated type is not an operator type at all.
- `E0035` — an ordinary operator applied to the wrong number of arguments.
