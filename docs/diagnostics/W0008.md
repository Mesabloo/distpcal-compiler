# W0008: unsafe cast

A specification calls `Fugue!FunAsSeq` or `Fugue!SetAsFun`. Both are *unsafe downcasts*: they
change how a value is viewed in a direction the type system's subtyping cannot justify, and the
generated program aborts if the value does not have the shape the cast assumes.

- `FunAsSeq(f)` reads a function as a sequence. It is defined only when `DOMAIN f = 1 .. n` for
  some `n`. The compiled form aborts otherwise.
- `SetAsFun(S)` reads a set of pairs as a function. Following Apalache, the result is unspecified
  when two pairs share a first component; the compiled form aborts there rather than picking one.

These are the only operators that raise this warning. The safe direction — a string used as a
sequence, a sequence used as a function, a uniform tuple used as a sequence — is performed by
subtyping with no operator written and no warning.

## Why it fires

```tla
EXTENDS Fugue, Naturals

\* @type: Seq(Int);
Reversed == FunAsSeq([i \in 1..3 |-> 4 - i])
```

`FunAsSeq` here is total in practice — the domain is visibly `1..3` — but the compiler does not
prove that, so the call is flagged.

## How to fix it

- If the precondition genuinely holds, the warning is advisory: silence it with `-Wno-unsafe`.
- Prefer a total construction where one exists: a sequence literal `<<...>>`, or
  `[i \in 1..n |-> e]` used directly as a sequence where the checker expects one.
- `Fugue!MkSeq(n, Op)` builds a sequence from a length and an element operator and is **not**
  unsafe — it raises no warning.
