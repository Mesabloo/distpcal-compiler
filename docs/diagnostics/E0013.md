# E0013: 'while' not labelled

A `while` statement is not immediately preceded by a real, user-written label.

The loop label is where each iteration begins and where the loop jumps back to. This compiler
follows PlusCal's default behaviour: it does not invent a label for a `while`, so you have to
write one, directly before the `while` and nothing else between.

## Why it fires

```tla
---- MODULE Example ----
(*--algorithm Example {
    variable x = 3;
    process (P = 0) {
    p1: print 1;
        while (x > 0) {
            x := x - 1;
        };
        goto p1;
    }
}*)
====
```

`print 1` sits between the label `p1` and the `while`, so the `while` itself is unlabelled.

## How to fix it

- Give the `while` its own label: `loop: while (x > 0) { ... }`.
- The same applies when a `while` is the first statement of an `if`/`either` branch — being first
  in a brace-delimited block is not the same as being labelled.
