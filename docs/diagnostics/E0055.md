# E0055: construct with no finite runtime representation

The algorithm uses `[A -> B]` — the set of all functions from `A` to `B` — or `[a : A, ...]` —
the set of all records of that shape. Both are infinite.

They are ordinary, well-typed TLA⁺ set expressions, so the type checker accepts them. But the
compiled program represents a set by its elements, and cannot do that for an infinite one. The
restriction applies when such a set is reachable from the algorithm's executable code.

## Why it fires

```tla
---- MODULE Example ----
EXTENDS Naturals

CONSTANTS
    \* @type: Address;
    PID

\* @type: Set(Int -> Int);
FuncSet == [Nat -> Nat]

(*--algorithm Example {
    process (P = PID) {
    p1: assert FuncSet = FuncSet;
        goto Done;
    }
}*)
====
```

`[Nat -> Nat]` is the set of all functions from naturals to naturals.

## How to fix it

- Iterate or quantify over a concrete, finite set of functions or records instead — build the ones
  you need explicitly.
- If the set is only used in an assertion for specification purposes, it cannot be compiled; drop
  it or move it out of the algorithm's reach.
