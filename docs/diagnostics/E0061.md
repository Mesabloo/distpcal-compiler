# E0061: construct with no Go counterpart

The program is well-formed and well-typed, but the Go backend has no way to compile one of its
constructs.

These are real limitations of the backend, not bugs. Known cases: an infinite base set (`Nat`,
`Int` used as a set), the `Bags` module, function equality, passing an operator as an argument, a
channel indexed by a tuple, and a `with (x \in e)` set binder. The message names the construct and
the reason.

## Why it fires

```tla
---- MODULE Example ----
EXTENDS Fugue

CONSTANTS
    \* @type: Address;
    PID

\* @type: (Int) => Int;
Sq(i) == i * i

(*--algorithm Example {
    process (P = PID)
        variables
            \* @type: Seq(Int);
            s = <<>>;
    {
    p1: s := MkSeq(3, Sq);
        goto Done;
    }
}*)
====
```

`MkSeq(3, Sq)` passes the operator `Sq` as an argument, which has no Go counterpart.

## How to fix it

- Rework the construct into one the backend supports: a bounded set instead of `Nat`, an explicit
  sequence literal instead of `MkSeq`, a single-binder `multicast`, a `with (x = e)` binder.
- Some cases have no equivalent — check the message; if it names something central to your
  algorithm, the Go target does not fit it.

## See also

- `W0008` — the unsafe casts, which *are* compilable (with a runtime abort on bad input).
