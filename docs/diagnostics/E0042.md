# E0042: type cannot be sent over a channel

A channel's declared element type is not sendable.

A value sent between processes has to have a concrete runtime representation. Operator values,
channels, `CONSTANTS`, unresolved rigid type variables — and anything containing one — do not, so
they are barred as a channel's element type. The check runs once, at the channel declaration,
rather than at every `send`.

## Why it fires

```tla
---- MODULE Example ----
CONSTANTS
    \* @type: Address;
    PID

(*--algorithm Example {
    fifos
        \* @type: Channel(Channel(Int));
        ch;
    process (P = PID) {
    p1: skip;
    }
}*)
====
```

`ch` would carry other channels — a channel is not itself sendable.

## How to fix it

- Send data, not capabilities: an `Int`, a record, a sequence. To tell a process about a channel,
  arrange the topology up front rather than sending the channel.
- A stuck type variable in the element type (`Channel(a)`) means the channel is under-specified —
  pin it to a concrete type.
