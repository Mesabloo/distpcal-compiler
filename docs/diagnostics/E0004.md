# E0004: wrong kind of annotation argument

An annotation's argument is given in a form the annotation does not accept — for example a
`@type` or `@mailbox` payload supplied as a quoted string where an inline argument is expected.

The argument count is right; the shape is not. In practice most malformed annotations surface as a
more specific diagnostic first: a missing or extra argument as `E0003`, an unparseable type as
`E0005`, an unparseable expression as `E0006`.

## How to fix it

- Write the payload inline after the colon: `\* @type: Int;`, `\* @mailbox: ch[self];` — not
  quoted, not bracketed.

## See also

- `E0003` — the annotation was given the wrong number of arguments.
- `E0005`, `E0006` — the payload is the right kind but does not parse.
- `E0007` — a `@mailbox` payload parses but is not `var[...]`-shaped.
