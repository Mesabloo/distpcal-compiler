# E0056: internal invariant violated in Typed2Computable

A compiler bug, not a problem with your specification.

The pass that lowers the type-checked program to its computable fragment relies on guarantees the
earlier passes are supposed to have established — that every unbounded quantifier and bare
temporal or action operator was already rejected, that no unresolved type placeholder survives
past type checking. This diagnostic fires when one of those guarantees did not hold. A well-formed
program that passes type checking and well-formedness should never reach it.

## Why it fires

One of the invariants above was broken before this pass ran: an earlier check that should have
rejected the input did not, or an earlier pass produced output it promised it would not. The
message names the specific invariant.

## How to fix it

- Report it, with the module you were compiling and the full message text. Include the
  specification if you can share it — the useful part is the input that slipped past the earlier
  checks.

## See also

- `E0055` — a genuinely non-computable construct (the set of all functions or all records),
  which is a real limitation and a normal error, not a bug.
- `E0057`, `E0058`, `E0060` — the same kind of internal-invariant check in the later passes.
