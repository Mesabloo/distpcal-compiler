# E0014: statement after 'if'/'either' is not labelled

An `if` or `either` that contains a label or a `goto` anywhere inside it must be followed by a
labelled statement, and is not.

When a branch contains a label or a `goto`, control can leave the branch mid-way and the two
branches can finish at different points. The statement after the `if`/`either` is where they
rejoin, so it needs its own label to be a valid jump target. This compiler follows PlusCal's
default: it does not invent that label.

## Why it fires

```tla
---- MODULE Example ----
(*--algorithm Example {
    variable x = 0;
    process (P = 0) {
    p1: if (x > 0) {
    p2:     print 1;
        } else {
            print 2;
        };
        print 3;
        goto p1;
    }
}*)
====
```

The then-branch has a label `p2`, so `print 3` — the statement after the `if` — must be labelled.

## How to fix it

- Label the statement after the `if`/`either`: `p3: print 3;`.
- Or remove the label/`goto` from inside the branches, if the branch bodies are single atomic
  steps that do not need one.

## See also

- `E0009` — a `goto` followed by unlabelled statements.
- `E0013` — a `while` not immediately preceded by a label.
