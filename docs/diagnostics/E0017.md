# E0017: duplicate annotation

The same annotation kind appears twice on one declaration, for a kind whose content can differ
between the copies.

`@type` and `@mailbox` carry content that two copies can disagree about — which type applies?
which channel is the mailbox? — so a repeat is ambiguous and rejected. The rule is syntactic, so
two *identical* copies are rejected too. `@parameter`, which carries nothing, only warns
(`W0003`).

## Why it fires

```tla
---- MODULE Example ----
CONSTANTS
    \* @type: Int;
    \* @type: Str;
    Foo
====
```

Two `@type` annotations on `Foo`, naming different types.

## How to fix it

- Keep one annotation, delete the rest.
- If two copies were meant to combine, they do not — pick the single type or channel that is
  correct.

## See also

- `W0003` — a repeated `@parameter`, which is redundant rather than ambiguous.
- `E0016` — an annotation on a site that does not accept it.
